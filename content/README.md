# content/

Every *content* string on the site comes from this directory — prose, names,
descriptions, dates, page titles. UI chrome labels are exempt and stay in the
components that render them: the /work filter buttons ("All", "With teams",
"On my own"), "CV", "Copy email" / "Email copied", "Dark" / "Light", "Back",
"Next" / "Previous", the section labels ("Work", "Writing", "Side projects",
"Tags") and the 404 text.

Frontmatter is validated with zod at load time (`lib/content/schemas.ts`) — a
malformed file fails the build. Loaders live in `lib/content/`; import them
from `@/lib/content`.

```
content/
  site.ts          typed module, the only non-Markdown source of copy
  posts/*.mdx      blog posts
  projects/*.md    work and side-project entries
  cv.json          résumé data for /llms.txt and /api/site.json
```

## site.ts

Exports `site` typed as `SiteInput` from `@/lib/content/schemas`.

| field | type | notes |
|---|---|---|
| `name` | string | |
| `title` | string | |
| `location` | string | |
| `email` | string | valid address |
| `github` | string | absolute URL |
| `linkedin` | string | absolute URL |
| `siteUrl` | string | absolute URL, no trailing slash |
| `repo` | string | `owner/name` on GitHub |
| `bio` | `(string \| {text, href?})[]` | runs of one sentence; `href` makes a link |
| `social` | `{label, href}[]` | GitHub, LinkedIn, Email (`mailto:`) |
| `stack` | `string[]` | the "Stack" line on /work |
| `workIntro` | string | the sentence under the /work heading |

## posts/\*.mdx

| field | type | required | notes |
|---|---|---|---|
| `title` | string | yes | |
| `date` | string | yes | `YYYY-MM-DD` |
| `tags` | string[] | no | defaults to `[]` |
| `summary` | string | yes | used in the RSS feed and page metadata |
| `draft` | boolean | no | defaults to `false`; drafts never appear in `getPosts()` |
| `accent` | string | no | `#rrggbb`; the only colour allowed on the site |

The file name is the slug, so `posts/equilibrium.mdx` → `/blog/equilibrium`.
`getPosts()` also computes `number` (1-based position in the date-ascending
list, rendered zero-padded to three digits) and `readingTime`.

## projects/\*.md

| field | type | required | notes |
|---|---|---|---|
| `name` | string | yes | |
| `description` | string | yes | 45 characters or fewer, enforced — a longer one clips the desktop row |
| `year` | string | yes | `"2024–"`, `"2021–2023"` or `"2019"`, enforced (en dash, U+2013) |
| `role` | string | yes | shown bold at the head of the /work meta line |
| `stack` | string[] | no | defaults to `[]` |
| `proof` | string | no | e.g. `"50k active players"` |
| `link` | string | yes | |
| `preview` | string | no | `"/static/images/previews/<slug>.webp"` — the image that floats beside the cursor when the row is hovered |
| `own` | boolean | yes | `true` → "On my own", `false` → "With teams" |
| `status` | `live \| archived \| store` | yes | |
| `featured` | boolean | no | shows in the home Work block |
| `lab` | boolean | no | shows in the home "Side projects" block |
| `order` — tie-break only; projects are sorted newest first by their `year` (ongoing on top, then end year, then start year), and `order` decides between projects sharing both.

The body is an optional longer paragraph.

### Preview images

`preview` points at `public/static/images/previews/<slug>.webp` — 640×400
(2× the 240×150 the page paints) at webp quality 80. They are generated by
`scripts/previews.mjs`, which is the record of where each one came from:

```
node scripts/previews.mjs                 # re-shoot the live sites, then encode
node scripts/previews.mjs --offline       # skip the browser, use fallbacks only
node scripts/previews.mjs flovi charles    # only these slugs
```

Each entry in that file's `SOURCES` table names one of three sources: a live
`url`, captured at 1280×800 with the gstack headless browser (`goto`,
`wait --load`, `cleanup --all`, `screenshot --viewport`); a `git` spec, for a
project image that was deleted from `public/` and is read back out of history
with `git show`; or a `file` still in the working tree. A `dead` note marks a
URL that no longer resolves — a parked domain, a delisted App Store app — and
sends the script straight to the fallback; delete the note to try the site
again. Screenshots are cover-cropped; app icons (`fit: 'pad'`) are centred on
a `#f5f5f5` canvas instead of being stretched to 16:10.

A project without a `preview` simply has no hover image; nothing else changes.

## cv.json

```jsonc
{
  "name": "", "title": "", "location": "", "email": "",
  "links": { "github": "", "linkedin": "", "site": "" },
  "summary": "",
  "experience": [
    {
      "company": "", "role": "",
      "start": "YYYY-MM", "end": null,      // null while the role is current
      "location": "",                        // "Finland, Remote"
      "stack": [],                           // the résumé's "Stack:" line
      "bullets": []                          // verbatim from the PDF
    }
  ],
  "skills": [{ "label": "", "items": [] }],  // ordered; the résumé's own groups
  "sideProjects": [
    { "name": "", "description": "", "links": [{ "label": "", "href": "" }] }
  ],
  "education": [{ "school": "", "degree": "", "years": "" }]
}
```

There is no /cv page — the footer's "CV" link is `/resume.pdf` itself, and
this file is read only by `/llms.txt` and `/api/site.json`.

`start` and `end` are `YYYY-MM`; `end` is `null` for a current role. `skills`
is an array, not a map, so the agent endpoints keep the résumé's own order.
`education.years` is free text ("2017–2019 (2 years completed)").
`content/cv.json` is transcribed from `public/resume.pdf` — keep the bullets
verbatim.

## Rules

- No lorem ipsum and no placeholder copy: every string here is real.
- Dates are ISO, en dashes in year ranges.
- `posts/` and `projects/` may be empty; the loaders return `[]`. `cv.json`
  is required by `/llms.txt` and `/api/site.json`, and throws if missing.
